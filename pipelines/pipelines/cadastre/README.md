# Cadastre

Spain's cadastral data, linked to INE municipalities:

- **Urban parcels** (13,209,772): the most detailed level of the map. 12,847,454 from the state
  Catastro (INSPIRE, April 2023) and 362,318 from the foral cadastres of Navarra, Álava, Bizkaia
  and Gipuzkoa (April–May 2023), in one dataset covering all 8,132 municipalities.
- **Cadastral zones** (*masas*): 1,148,384 urban blocks (*manzanas*) and 175,210 rural polygons
  (*polígonos*), state Catastro only. The blocks aren't on the map; each urban parcel keeps its block.
- **Cadastral polygons** (183,133, every municipality): the state Catastro's rural polygons plus
  the foral cadastres', on the map as a fixed-only layer.
- **Buildings**: a pipeline exists (`buildings.py`, tested on two municipalities) but isn't run or
  on the map for now.

All from local archives downloaded in 2023 for an earlier project, copied into `data/raw/` first:

```sh
ARCHIVE="$HOME/Documents/Dratio/Dratio - Data Projects/20230627 - Catastro 2023"
# Once per archive: copy what's used out of it (the archive itself is left untouched).
python pipelines/cadastre/import_inspire.py zoning  "$ARCHIVE/catastro - Inspire"
python pipelines/cadastre/import_inspire.py parcels "$ARCHIVE/catastro - Inspire"
python pipelines/cadastre/import_foral.py "$ARCHIVE"
# Then, in this order (zones first: parcels use them for blocks and municipality codes).
python pipelines/cadastre/cadastral_zones.py      # ~2 min, ~7 GB of memory
python pipelines/cadastre/cadastral_parcels.py    # ~10 min, ~14 GB of memory
python pipelines/cadastre/foral_parcels.py        # ~30 s
python pipelines/cadastre/rural_polygons.py       # ~20 s
```

that suggests official cadastral cartography.

## State Catastro: validity

A snapshot as of April 2023: Catastro updates the INSPIRE downloads twice a year. Each zone keeps
`valid_from` (Catastro's `beginLifespanVersion`, 2000–2023).

## Cadastral zones: processing

- **Zone types**: Catastro's `MANZANA` → `urban_block`, `POLIGONO` → `rural_polygon`. Any other
  type stops the run.
- **Zones in pieces**: 2,232 features are pieces of 962 zones (same reference, same municipality);
  each zone becomes one row with the union of its pieces.
- **Geometry**: reprojected from each municipality's UTM zone to EPSG:4326; 16,328 invalid
  geometries repaired with `make_valid` (keeping only polygonal parts).
- **Labels** are read as text (GDAL would guess numbers in some files and drop leading zeros:
  polygon `008` → `8`).
- **Municipality**: Catastro numbers municipalities its own way: its code isn't INE's, and its
  "provinces" 51–56 aren't INE's either. By position, their zones fall in Murcia (51), Asturias
  (52), Cádiz (53), Pontevedra (54), Ceuta (55) and Melilla (56); they look like Catastro's own
  offices, but that's not stated in the data.
  So each zone gets the IGN municipality that contains a point inside it; 275 zones on the
  coastline outside every IGN municipality get the nearest one.

## Cadastral zones: overlap between polygons and blocks

Catastro's rural polygons don't stop where the urban blocks start: they cover the whole municipal
area, the urban core included, and the blocks lie on top as a finer subdivision. In Madrid, 99.9 %
of the blocks' area is also inside some polygon (polygons 900–904 among them); in Sevilla, 97 %.

The GeoParquet keeps both, **as published**. Neither is on the map (decided on 2026-10-25): it goes
from census sections straight to urban parcels, and each parcel keeps its block (`zone_id`). If
zones are ever needed on a map, clip each rural polygon by its municipality's blocks first.

## Cadastral zones: checks (2023-04 snapshot)

- 1,323,594 zones, unique ids, all geometries valid.
- 7,608 of 8,132 INE municipalities have zones; the 524 without are exactly those of Navarra,
  Bizkaia, Gipuzkoa and Álava.
- Apart from Catastro's offices 51–56, only about 120 zones fall in a province other than their
  file's (along provincial borders).

## Cadastral zones: identifiers

`es:catastro:zone:{Catastro municipality code}:{reference}`, e.g.
`es:catastro:zone:15015:73795NJ6077N` (urban block) or `es:catastro:zone:14012:14012A003` (rural
polygon). Urban block references are only unique within a municipality, so the id carries
Catastro's municipality code too. Parent: the INE municipality, `es:ine:mun:{code}`.

## Urban parcels: state Catastro

`cadastral_parcels.py` reads every municipality's parcels, keeps the urban ones and writes one file
per Catastro province (they don't fit in memory together):

- **Urban or rural**: by reference. Rural references are Catastro municipality (5) + a letter +
  polygon (3) + parcel (5), e.g. `12068A00200237`; everything else is urban.
- **Parcels in pieces**: one row each; the pieces' areas add up (each carries its own). Their
  labels can differ in padding only (`008`, `08`), so they aren't compared.
- **Block** (`zone_id`): the urban block a point inside the parcel lies in, within the same
  municipality: 92 % of urban parcels. By position because parcel and block references don't
  always agree (the sheet's last letter can differ: `5910002XJ2451N` is in block `59100XJ2451S`),
  and some parcels (`000700100XJ24B`) have a reference format no block has.
- **INE municipality**: Catastro municipality code → INE code from the cadastral zones (the INE
  municipality most of its zones lie in; `common/catastro.py`).
- 12,847,454 urban parcels; all geometries valid after repair.

## Urban parcels: foral cadastres

Navarra and the three Basque provinces keep their own cadastres. `import_foral.py` copies their
files into `data/raw/cadastre_foral/2023-05/`; `foral_parcels.py` normalizes them into the same
dataset (one file per province: `01`, `20`, `31`, `48`), with `source` naming the cadastre.

| Territory | Files | Urban parcels | How urban is told | Date | License |
|---|---|---|---|---|---|
| Navarra | `Catastro.gpkg`, layer `CATAST_Pol_ParcelaUrba` | 182,939 | Its own layer (mixed parcels, `ParcelaMixta`, mostly rural, are left out) | 2023-04-21 | CC BY 4.0, "Información geográfica propiedad del Gobierno de Navarra" (in the layers' metadata) |
| Bizkaia | One zip per municipality, `{code}_Parcela.shp` + `{code}_Subparcela.shp` | 69,052 | A parcel with an urban subparcel (`Codigo_Nat = Urb`) that isn't scattered (`Diseminado = 0`): houses on large rural estates stay out, as in the state Catastro | 2023-05-02 | CC BY 4.0 per datos.gob.es; exact attribution wording not found |
| Gipuzkoa | `KATASTROA_CATASTRO.zip`, `HIRILUR_URBANO.shp` | 58,511 | Its own layer | 2023-03-17 | **Not confirmed**: check before publishing |
| Álava | One zip per municipality, `parcela_urbana.shp` | 51,816 | Its own layer | 2023-04-28 | CC BY 4.0, Diputación Foral de Álava (INSPIRE metadata) |

- **Identifiers**: `es:{territory}:parcel:{municipality}:{reference}`, with each source's own
  municipality number and reference (`REFCAT` in Navarra, `Erreferentz` in Gipuzkoa, polygon-parcel
  in Bizkaia and Álava).
- **INE municipality**: by position. Each source numbers municipalities on its own; with the
  province in front that's INE's code for 95–99.8 % of parcels, but not always (Álava's 26 and 35
  don't exist in INE).
- **No blocks**: none of the four has them, so `zone_id` is empty and the parent is the municipality.
- **Area**: measured on the geometry (ETRS89 / UTM 30N), since not every source gives it.

Together with the state Catastro, every one of the 8,132 municipalities has urban parcels.

## Cadastral polygons

`rural_polygons.py` puts the state Catastro's rural polygons (from the cadastral zones) and the
foral cadastres' together, each linked to the INE municipality it lies in (by position):

| Source | Polygons | From |
|---|---|---|
| Catastro | 175,210 | Cadastral zones with `zone_type = rural_polygon` |
| Bizkaia | 4,152 | `{code}_Poligono.shp` per municipality |
| Navarra | 2,523 | `Catastro.gpkg`, layer `CATAST_Pol_Poligono` (facerías included) |
| Gipuzkoa | 875 | No polygon layer: each polygon is the union of its rural parcels (`LANDALUR_RUSTICA.shp`, references `{polygon}-{parcel}`), so it covers rural land only |
| Álava | 373 | `poligono.shp` per municipality |

Polygons from the state Catastro and most foral cadastres also cover urban land (see the overlap
above); as their own fixed-only map layer, they're never drawn over the urban parcels.

Ids: `es:catastro:zone:{municipality}:{reference}` (the state Catastro's zone id) and
`es:{territory}:polygon:{municipality}:{polygon}` for the foral ones, with each source's own
municipality number. Output: `rural_polygons_2023.parquet` (`id`, `polygon`,
`source_municipality_code`, `municipality_code`, `source`, `parent_id`, `geometry`).

## Output

In `data/processed/cadastre/`:

- `cadastral_zones_2023-04.parquet`: GeoParquet 1.1 (zstd, bbox covering column, row groups of
  100,000), EPSG:4326, sorted by `id`; 2.5 GB at full resolution. Columns: `id`, `reference`,
  `zone_type`, `label` (block or polygon number), `catastro_municipality_code`, `valid_from`,
  `municipality_code` (INE), `parent_id`, `geometry`.
- `cadastral_parcels_2023-04/{province}.parquet`: urban parcels, one file per province (Catastro's
  provinces, including its offices 51–56, plus the four foral ones), all with the same schema:
  `id`, `reference`, `area_m2`, `valid_from`, `catastro_municipality_code` (state Catastro only),
  `municipality_code` (INE), `zone_id` (block; state Catastro only), `parent_id` (block or
  municipality), `source` (`catastro`, `navarra`, `bizkaia`, `gipuzkoa`, `alava`), `geometry`.
  Read them together as a Parquet dataset.
- `.meta.json` files with each run's details.
